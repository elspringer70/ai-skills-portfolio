# Tools

This skill can work as a standalone prompt or as part of a connected product operations workflow.

## Core Integrations

### JIRA

Use JIRA to:

- Read existing tickets
- Create epics, stories, and tasks
- Add labels, priorities, components, and dependencies
- Update ticket descriptions with acceptance criteria
- Comment with open questions or readiness notes

### Confluence

Use Confluence to:

- Pull product requirements and decision logs
- Link tickets back to source documentation
- Publish ticket breakdown summaries
- Keep sprint planning notes connected to implementation work

### Slack or Microsoft Teams

Use team chat to:

- Summarize engineering clarification threads
- Extract decisions from stakeholder conversations
- Draft follow-up questions for unresolved requirements
- Notify owners when tickets are ready for review

### Google Docs or Notion

Use docs tools to:

- Convert PRD sections into ticket candidates
- Preserve draft versions before creating JIRA issues
- Create public-safe portfolio examples from synthetic notes

### GitHub

Use GitHub to:

- Link implementation tasks to repositories
- Reference pull requests in release notes
- Compare ticket requirements against shipped code or open PRs

## Optional Advanced Integrations

### OpenAPI or Postman

Use API specs to:

- Identify endpoint changes required by a ticket
- Clarify request and response behavior
- Detect missing error states
- Generate API-focused acceptance criteria

### Analytics Tools

Use analytics platforms to:

- Recommend event names and properties
- Connect ticket outcomes to success metrics
- Identify funnel or workflow drop-off points

### Compliance Knowledge Base

Use approved policies, checklists, or example language to:

- Flag regulated product areas
- Identify review requirements
- Suggest compliance-safe open questions
- Avoid unsupported claims in user-facing copy

## One-Day Build

A simple version can be built as:

- A markdown prompt
- A sample input and output
- A lightweight web form or CLI script
- Manual copy and paste into JIRA

## Portfolio-Worthy Build

A stronger public version could include:

- A demo interface with synthetic fintech examples
- A before-and-after ticket breakdown view
- Export to markdown, JSON, or JIRA-ready format
- Readiness scoring for each ticket
- A mock integration layer showing how tickets would be created
- Evaluation examples showing strong, weak, and improved outputs
